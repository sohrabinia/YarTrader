# YarTrader v0.2.0 — Clean Production Migration Manifest

Baseline: `16983fb8770a5c0c2daca4e875908f569ebbfff0`

This document is the migration contract for v0.2.0. The previous project is a source library, not a package to carry forward wholesale.

## KEEP / MIGRATE

- Windows production service + NSSM + LocalSystem deployment.
- IIS reverse proxy and existing production ports.
- MT5 terminal, MT5 bridge, demo account/server binding, and bridge token configuration.
- Canonical 30-symbol universe and market-universe configuration.
- ResearchRuntime and real MT5 market-data path.
- Existing CognitiveReplayLoop learning components: ObservationBrain → PatternDiscoveryEngine → HypothesisEngine → SimulationBrain → JudgeBrain → ActiveLearningEngine → MarketMemorySystem.
- Decision/risk/safety gates, including 0.5% target risk, 2% hard ceiling, RR >= 1.5, and daily-loss 8% protection.
- XAUUSD-only DEMO order scope and LIVE hard-disable.
- Google/Gmail-only customer authentication contract; internal/admin authentication remains separate.
- YarOperator loopback-only integration and owner authentication. GitHub access is NOT granted to YarOperator.
- Existing UI/UX assets only where they map to the v0.2.0 product modes: Analysis, Backtest, Demo Trade, Signal, Prop.

## REBUILD / REFACTOR

- Canonical market universe registry is now owned by `src/Market/Universe/symbol_registry.py`, not the retired Shadow namespace.
- Fractal base detection is indicator-free in the online path; ATR/True Range calculation is removed.
- Runtime health must use authoritative central/provider state rather than legacy mutable trackers.
- Learning memory is accepted only when provenance and schema match the current brain contract.
- UI data must never use fabricated similarity, performance, or market fallback values.

## ARCHIVE / RETIRE FROM PRODUCTION PATH

- PredictiveShadowEngine and ShadowTradingEngine execution paths.
- Shadow mode as a product mode; Signal is the user-facing non-execution signal product.
- Deprecated IntelligenceWorker runtime execution path.
- Legacy research_tracker as an authority for production health.
- Old indicator-driven execution paths.
- Synthetic/fallback evidence that can be mistaken for live or learned market evidence.
- Contradictory historical audit documents; retain only as clearly labeled historical records.

## DATA / DATABASE RULE

1. Inventory first. Never clear or overwrite learning data before schema/provenance inspection.
2. Preserve a backup before any mutation.
3. Keep only records with real market provenance, valid timestamps, compatible schema, and no look-ahead leakage.
4. Retire Shadow-only, synthetic, test, obsolete-strategy, unknown-provenance, or incompatible records.
5. If no valid learning memory remains after the audit, initialize a clean empty memory store rather than carrying questionable history.

## SERVER PRESERVATION RULE

No server rebuild is part of v0.2.0. Preserve existing Windows service, NSSM, LocalSystem identity, Python virtual environment, IIS, ports, MT5 terminal/bridge, machine environment variables, Google configuration, DB secure token, runtime/log directories, and YarOperator loopback boundary unless a forensic check proves a specific setting incompatible.

## DEMO EXECUTION TRUTH

`AUTONOMOUS_DEMO_TRADING_ENABLED` is fail-closed. Missing/empty/false values block order dispatch. Only explicit runtime value `true` enables the DEMO execution branch; all other safety/risk gates remain mandatory.
