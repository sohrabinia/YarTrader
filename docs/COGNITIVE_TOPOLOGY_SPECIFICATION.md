# Multi-Asset & Multi-Timeframe Cognitive Architecture (v8.0)
## TradeYar AI — Definitive Cognitive Architecture Lock

This document outlines the definitive SRE specifications and mathematical design schemas of the **Multi-Asset & Multi-Timeframe Cognitive Architecture** implemented inside TradeYar AI v8.0.

---

## 1. Cognitive Topology & Independence Mandate

TradeYar AI does not process multiple assets with shared brain structures or monolithic timeframe states. Instead, every symbol represents a completely independent cognitive universe.

```text
Market Data Layer
       │
       ▼
Symbol Runtime Manager (SymbolRuntimeManager)
       │
       ├─────────────────────────┬─────────────────────────┐
       ▼                         ▼                         ▼
   [ XAUUSD Context ]        [ BTCUSD Context ]        [ EURUSD Context ]
       │
       ├──── Custom Frame Engine 1   ──► [Memory | Pattern | Shadow | Judge | Analytics]
       ├──── Custom Frame Engine 4   ──► [Memory | Pattern | Shadow | Judge | Analytics]
       ├──── Custom Frame Engine 16  ──► [Memory | Pattern | Shadow | Judge | Analytics]
       ├──── Custom Frame Engine 64  ──► [Memory | Pattern | Shadow | Judge | Analytics]
       └──── Custom Frame Engine 256 ──► [Memory | Pattern | Shadow | Judge | Analytics]
```

### 1.1 Complete Brain Isolation
- Gold (`XAUUSD`) Frame 64 learning outputs never contaminate Bitcoin (`BTCUSD`), nor do they leak to Gold Frame 4.
- Every `Symbol + Timeframe` combination maintains isolated tick buffers, base/node memories, pattern outcome statistics, and shadow trading position lifecycles.

## 2. Multi-Timeframe Decision Fusion

The platform synthesizes symbol-level active trading decisions/signals **solely** from its own internal timeframe contexts.

### 2.1 Weight Allocations
A mathematical weighted voting mechanism is employed across active horizons of the same symbol:
- **Micro (Frame 1)**: Weight = `1.0`
- **Short (Frame 4)**: Weight = `1.5`
- **Medium (Frame 16)**: Weight = `2.0`
- **Medium-High (Frame 64)**: Weight = `2.0`
- **Macro (Frame 256)**: Weight = `3.0`

$$W_{Fused} = \sum_{tf \in TF} Weight(tf) \times \left( \frac{Confidence(tf)}{100} \right) \times DirectionSign(tf)$$

### 2.2 Fusion Delivery
Signals are generated by consolidating these weights. If different timeframes conflict, the engine outputs a neutral consolidated state (`WAIT`) instead of generating mixed or compromised signal coordinates.

## 3. Scale, Scheduling, & SRE Backpressure

Processing 30 active symbols across 5 isolated frames translates to **150+ concurrent independent cognitive engines**.

### 3.1 Worker Queue Allocation
- **Isolated Queues**: `SymbolRuntimeManager` registers independent `queue.Queue` buffers with a capped capacity (`maxsize=1000`) for every symbol context.
- **Sliding Queue Backpressure**: If ticks exceed processing thread capacity, the sliding window drops the oldest un-processed ticks to preserve real-time telemetry responsiveness without blocking.

### 3.2 Symbols Limit
- Hard-capped SRE ceiling at **30 active concurrent unique symbols** defined inside `config/system_limits.yaml`.
- Dynamic registrations checking these limits are strictly guarded.
