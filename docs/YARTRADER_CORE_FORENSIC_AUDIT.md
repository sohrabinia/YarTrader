## 1. Executive Summary

This forensic report delivers an absolute, read-only architectural and runtime analysis of the YarTrader decision core. It establishes source-level and runtime-level truth regarding which components produce live trading decisions, which components serve as legacy or compatibility wrappers, how learning operates, why zero trades have been generated, and how Shadow Trading will be completely eliminated to achieve Global Shadow = Zero.

### Key Discoveries:
1. **Canonical Runtime Decision Producer**: Live trading decisions (`BUY`, `SELL`, `WAIT`, `AVOID`) are generated by `ExecutionIntelligencePlanner.generate_execution_plan()` (`src/Intelligence/Execution/execution_planner.py:17`), orchestrated by `ExecutionIntelligenceCore` (`src/Intelligence/Execution/core.py:126`) inside `ResearchRuntime.run_once()` (`src/Application/Runtime/research_runtime.py:187`).
2. **No-Trade Root Cause Classification**: `E — Configuration/environment failure` & `A — Decision generation failure (Market Structural Range Compression)`. In normal market conditions, `ExecutionIntelligencePlanner` evaluates `narrative.get("state") in ["COMPRESSION", "RANGE"]` (`src/Intelligence/Execution/execution_planner.py:94`), which forces action to `"WAIT"`. When actionable `BUY`/`SELL` signals are generated, `ResearchWorker` applies Risk Gates (`MINIMUM_RR=1.5`, `MINIMUM_CONFIDENCE=50.0`) and Cooldown (`cooldown_sec=300.0`), preventing duplicate order spamming.
3. **Canonical Architectural Engine vs. Runtime Active Engine**:
   - `DecisionEngine` (`src/Decision/Intelligence/engine.py:24`) is the canonical *architectural* decision engine registered in DI, but it evaluates portfolio allocation weights (`DecisionContext`) rather than direct trade entries (`BUY`/`SELL`).
   - `AutonomousDecisionEngine` (`src/Decision/engine.py:7`) is a legacy asset-scoring engine from earlier portfolio allocation iterations.
   - `DecisionReasoningFramework` (`src/Decision/Engine/engine.py:10`) is a wrapper providing backward compatibility.
4. **`ProfessionalSignalEngine` Status**: `ProfessionalSignalEngine` (`src/Decision/Intelligence/professional_signal_engine.py:35`) is **ACTIVE SOURCE / TEST ACTIVE ONLY**. It is instantiated in unit tests (`tests/YarTrader.Tests/Execution/test_autonomous_demo_runtime.py:29`), but zero live background workers (`ResearchWorker`, `ShadowWorker`, `YarTraderWindowsService`) call it.
5. **Learning & Memory Truth**: `MarketMemorySystem` (`src/Research/Brain/memory.py:9`) and `experiences_memory.json` (~54.9 MB) write situational logs and past outcomes. `JudgeBrain` (`src/Research/Brain/judge.py:5`) evaluates trade decisions post-mortem. Neither `JudgeBrain` nor `MarketMemorySystem` mutates decision logic or parameters dynamically during execution; learning operates as **RETRIEVAL-BASED ADAPTATION & PASSIVE LOGGING**.
6. **Critical Error Path Defect**: `app/workers/shadow_worker.py:73` references `os.path.join()` inside its exception recovery block, but `import os` is missing from the module imports. If an unhandled exception occurs in `ShadowWorker._run_loop()`, the exception handling path fails with a `NameError`.
7. **Shadow Trading Elimination Directive**: Shadow Trading will be completely removed across runtime, workers, backend APIs, frontend UI, `/health` endpoints, configuration, and data models. Learning and evaluation systems (`TradeEvaluator` -> `JudgeBrain` -> `MarketMemorySystem` -> `FractalPatternMemory`) will be decoupled and reconnected to receive canonical Demo/Simulation trade outcomes directly. Global `SHADOW = ZERO`.
8. **Live Trading Safety**: `LIVE_TRADING_ENABLED = False` and `REAL_ORDERS = 0` are hard-locked across all execution boundaries (`MetaTrader5Provider`, `DemoExecutionEngine`, `RealMT5BrokerAdapter`).

   - `src/Decision/Intelligence/engine.py` (`DecisionEngine`) is designed as the canonical decision interface, but the background worker pipeline invokes `ExecutionIntelligenceCore` / `ExecutionIntelligencePlanner` directly.
3. **Defect 3: Multiple Unconsolidated Decision Contract Models**:
