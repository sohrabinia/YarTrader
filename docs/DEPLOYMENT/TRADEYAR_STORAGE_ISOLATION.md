# TradeYar AI Runtime Storage Isolation Specification

## 1. Directory Structure Map
To guarantee operational isolation and clean storage boundaries, all runtime files generated by the RG_V3_AI platform are strictly localized inside the dedicated TradeYar Storage Root (typically configured as drive `H:` in standard Windows production environments).

### Isolated Subdirectories
```
H:\TradeYarAI\
│
├── Logs\          - JSON formatted structured log records (tradeyar_ai.log)
├── Reports\       - Trace-complete E2E scenario, backtest, and decision reports
├── Runtime\       - Process-level tracking states
├── Cache\         - Temporary memory cache dumps
├── Data\          - Stream-ingested rates snapshots
├── Diagnostics\   - Subsystem diagnostic check logs
└── Temp\          - Isolated temporary scratchpads
```

---

## 2. Configuration Method
The absolute storage root directory is defined using the single source of truth parameter:

`TradeYarStorageRoot`

This parameter can be loaded dynamically from environment variables, fallback settings, or direct configuration injections inside `ProductionConfig` and `TradeYarStorageManager`:
- **Windows Fallback default**: `H:\TradeYarAI\`
- **Unix Fallback default**: `/tmp/TradeYarAI/`

All system paths (logs, reports, diagnostics, cache, temp) are strictly derived as subfolders under this storage root, ensuring complete platform-specific portability.

---

## 3. Operational Security Rationale
1. **OS Directory Protection**: Restricting runtime writes strictly to the isolated storage root prevents any malicious/corrupted writes from cluttering standard system directories (`C:\Windows\`, `/var/`, `/etc/`).
2. **Read-Only Non-Trading Seal**: All files represent strictly descriptive logs, diagnostic states, or passive evidence reports. No active trade execution signals or broker-connect credentials are saved.
3. **Data Loss Prevention**: Localizing caches, diagnostics, and states under a single H: drive makes backup and recovery extremely simple.
